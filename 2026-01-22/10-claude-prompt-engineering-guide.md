## 요약

이 문서는 Anthropic 공식 Claude 프롬프트 엔지니어링 가이드의 핵심 4개 섹션을 통합 정리한 것입니다. **프롬프트 엔지니어링 개요**, **Chain of Thought**, **시스템 프롬프트**, **명확하고 직접적인 지시** 기법을 다룹니다.

## 1. 프롬프트 엔지니어링 개요 (Overview)

### 프롬프트 엔지니어링이란?

프롬프트 엔지니어링은 Claude에게 작업을 효과적으로 전달하여 원하는 출력을 얻는 기술입니다.

### 권장 적용 순서

```
1. 명확하고 직접적으로 (Be clear and direct)
         ↓
2. 예시 사용 (Use examples - Few-shot)
         ↓
3. 생각하게 하기 (Chain of Thought)
         ↓
4. XML 태그 사용 (Use XML tags)
         ↓
5. 역할 부여 (System prompts)
         ↓
6. 응답 미리채우기 (Prefill responses)
         ↓
7. 프롬프트 체이닝 (Chain prompts)
```

### 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **명확성** | 모호함 없이 구체적으로 요청 |
| **맥락 제공** | 배경 정보와 목표 명시 |
| **구조화** | XML 태그, 마크다운으로 정리 |
| **예시 제공** | 원하는 출력 형태 보여주기 |
| **반복 테스트** | 실험하고 개선하기 |

### 성공 기준 먼저 정의

프롬프트 작성 전:
1. **성공이란 무엇인가?** - 명확한 목표 설정
2. **어떻게 측정할 것인가?** - 평가 기준 수립
3. **테스트 케이스는?** - 다양한 시나리오 준비

## 2. Chain of Thought (생각의 사슬)

### CoT란?

Claude가 최종 답변 전에 **단계별로 생각하도록** 유도하는 기법입니다. 복잡한 문제에서 정확도를 크게 향상시킵니다.

### 언제 사용하나?

| 적합한 경우 | 불필요한 경우 |
|-------------|---------------|
| 수학 문제 | 단순 사실 질문 |
| 논리 추론 | 번역 |
| 복잡한 분석 | 창작 글쓰기 |
| 다단계 작업 | 요약 |
| 코드 디버깅 | 분류 작업 |

### 기본 사용법

**방법 1: 명시적 지시**
```
이 문제를 단계별로 풀어주세요.
[문제 내용]
```

**방법 2: XML 태그로 구조화**
```xml
<problem>
수학 문제 내용
</problem>

<instructions>
1. 문제를 분석하세요
2. 단계별로 풀이 과정을 보여주세요
3. 최종 답을 제시하세요
</instructions>
```

### CoT 프롬프트 예시

#### ❌ 나쁜 예 (CoT 없음)
```
2x + 5 = 13일 때 x는?
```

#### ✅ 좋은 예 (CoT 적용)
```
다음 방정식을 풀어주세요.
단계별로 풀이 과정을 보여주세요.

2x + 5 = 13
```

### 응답 형식 지정

```xml
<thinking>
여기에 단계별 사고 과정을 작성하세요
</thinking>

<answer>
최종 답변만 여기에
</answer>
```

### CoT 고급 기법

#### 1. 자기 검증 (Self-Verification)
```
문제를 풀고, 답이 맞는지 검증해주세요.
검증 과정에서 오류를 발견하면 수정하세요.
```

#### 2. 다중 경로 추론
```
이 문제를 두 가지 다른 방법으로 풀어주세요.
두 결과가 일치하는지 확인해주세요.
```

#### 3. 분해 전략
```
이 복잡한 문제를 작은 하위 문제로 나누세요.
각 하위 문제를 순서대로 해결하세요.
```

## 3. 시스템 프롬프트 (System Prompts)

### 시스템 프롬프트란?

대화 시작 전에 Claude의 **행동, 역할, 제약조건**을 설정하는 특별한 지시사항입니다.

### 시스템 프롬프트 vs 사용자 프롬프트

| 구분 | 시스템 프롬프트 | 사용자 프롬프트 |
|------|----------------|----------------|
| **위치** | 대화 시작 전 | 대화 중 |
| **목적** | 전체 행동 지침 | 구체적 요청 |
| **지속성** | 전체 대화에 적용 | 해당 턴에만 적용 |
| **예시** | "너는 친절한 고객 상담사야" | "환불 방법 알려줘" |

### 시스템 프롬프트 구성요소

```xml
<system_prompt>
<!-- 1. 역할 정의 -->
당신은 [역할]입니다.

<!-- 2. 핵심 지침 -->
다음 원칙을 따르세요:
- 원칙 1
- 원칙 2

<!-- 3. 응답 스타일 -->
응답 시:
- 형식
- 톤
- 길이

<!-- 4. 제약조건 -->
다음은 하지 마세요:
- 제약 1
- 제약 2

<!-- 5. 예시 (선택) -->
<example>
좋은 응답 예시
</example>
</system_prompt>
```

### 역할 부여 예시

#### 코드 리뷰어
```
당신은 10년 경력의 시니어 개발자입니다.
코드 리뷰 시:
- 버그와 보안 이슈를 우선 확인
- 개선 제안은 구체적으로
- 칭찬할 부분도 언급
- 코드 예시와 함께 설명
```

#### 기술 문서 작성자
```
당신은 기술 문서 전문가입니다.
- 명확하고 간결하게 작성
- 전문 용어는 처음 사용 시 정의
- 단계별 지침 제공
- 예시 코드 포함
```

#### 고객 상담사
```
당신은 친절한 고객 상담사입니다.
- 공감하며 응대
- 해결책 중심으로 안내
- 전문 용어 대신 쉬운 말 사용
- 추가 도움 필요 여부 확인
```

### 시스템 프롬프트 모범 사례

1. **구체적으로**: "친절하게" → "따뜻한 톤으로, 이모지 1-2개 사용"
2. **우선순위 명시**: 가장 중요한 지침을 먼저
3. **예시 포함**: 원하는 응답 형태 보여주기
4. **제약조건 명확화**: "~하지 마세요"보다 "~만 하세요"
5. **테스트 반복**: 다양한 입력으로 검증

## 4. 명확하고 직접적으로 (Be Clear and Direct)

### 핵심 원칙

> **Claude를 처음 일하는 능력 있는 신입 직원으로 생각하세요.**  
> 그는 맥락을 모르지만, 정확한 지시가 있으면 잘 수행합니다.

### 명확성의 요소

| 요소 | 설명 | 예시 |
|------|------|------|
| **구체성** | 정확한 요구사항 | "3문장으로 요약" vs "짧게 요약" |
| **맥락** | 배경 정보 제공 | "B2B SaaS 제품 설명을 위해..." |
| **형식** | 출력 형태 지정 | "JSON으로", "표로", "글머리로" |
| **예시** | 원하는 결과 보여주기 | 입력-출력 쌍 제공 |

### ❌ 모호한 프롬프트 vs ✅ 명확한 프롬프트

#### 예시 1: 요약
```
❌ "이 글 요약해줘"

✅ "이 글을 다음 형식으로 요약해주세요:
   - 핵심 주장 (1문장)
   - 주요 근거 (3개, 각 1문장)
   - 결론 (1문장)"
```

#### 예시 2: 코드 작성
```
❌ "로그인 기능 만들어줘"

✅ "Python Flask로 로그인 API를 만들어주세요:
   - POST /api/login 엔드포인트
   - email, password 입력 받음
   - JWT 토큰 반환
   - 실패 시 401 에러
   - SQLAlchemy ORM 사용"
```

#### 예시 3: 분석
```
❌ "이 데이터 분석해줘"

✅ "이 판매 데이터를 분석해주세요:
   1. 월별 매출 추이
   2. 상위 5개 제품
   3. 전년 대비 성장률
   출력 형식: 각 항목별 표 + 인사이트 1-2문장"
```

### 직접적 지시의 힘

#### 간접적 (비효율적)
```
"혹시 이 코드에서 문제가 있다면 알려주실 수 있을까요?"
```

#### 직접적 (효율적)
```
"이 코드의 버그를 찾고 수정해주세요."
```

### 맥락 제공 템플릿

```xml
<context>
배경: [상황 설명]
목표: [달성하려는 것]
대상: [누구를 위한 것]
제약: [제한 사항]
</context>

<task>
[구체적인 요청]
</task>

<output_format>
[원하는 출력 형식]
</output_format>
```

### 체크리스트

프롬프트 작성 시 확인:

- [ ] **무엇을**: 정확히 무엇을 원하는가?
- [ ] **왜**: 이 작업의 목적은?
- [ ] **어떻게**: 어떤 형식/스타일로?
- [ ] **얼마나**: 길이/양/범위는?
- [ ] **제약**: 하지 말아야 할 것은?

## 종합 정리

### 프롬프트 작성 공식

```
효과적인 프롬프트 = 
    명확한 지시 (Be Clear and Direct)
  + 적절한 역할 (System Prompt)
  + 단계별 사고 (Chain of Thought)
  + 구조화 (XML Tags)
  + 예시 (Few-shot)
```

### 상황별 기법 선택

| 상황 | 권장 기법 |
|------|----------|
| 간단한 질문 | 명확하고 직접적으로 |
| 복잡한 분석 | CoT + XML 태그 |
| 일관된 톤/스타일 | 시스템 프롬프트 |
| 특정 형식 출력 | 예시 + 형식 지정 |
| 다단계 작업 | 프롬프트 체이닝 |

### 프롬프트 개선 사이클

```
1. 초안 작성
      ↓
2. 테스트 (다양한 입력)
      ↓
3. 결과 평가
      ↓
4. 문제점 파악
      ↓
5. 프롬프트 수정
      ↓
(반복)
```

---

## 핵심 포인트

1. **명확성이 최우선**: 모호함을 제거하고 구체적으로 요청
2. **맥락은 힘**: 배경, 목적, 대상 등 충분한 정보 제공
3. **CoT로 정확도 향상**: 복잡한 문제는 단계별 사고 유도
4. **시스템 프롬프트로 일관성**: 역할과 규칙을 사전 정의
5. **반복 개선**: 테스트하고, 평가하고, 수정하기
